Problem 1 (:1):
Which technique is commonly used in program verification?
A) Trial and error debugging
B) Static analysis
C) Mutation testing
D) Random input testing
Correct Answer: B

Solution:
Static analysis examines code without executing it, searching for potential bugs or vulnerabilities. It's frequently used in program verification.

Explanation:
Trial and error debugging, mutation testing, and random input testing are methods to detect issues but don't provide formal correctness guarantees like static analysis.

Common mistake note:
Common mistake: Selecting A or D, which are testing techniques that might reveal bugs but don't guarantee program correctness.

Problem 2 (:2):
What is a key advantage of model checking in program verification?
A) Efficient handling of large codebases
B) Absolute performance optimization
C) No prior system knowledge required
D) Guaranteed absence of runtime errors
Correct Answer: D

Solution:
Model checking automatically checks if a formal model satisfies a given property. It can ensure the absence of certain runtime errors.

Explanation:
While model checking can handle large codebases, it doesn't guarantee performance optimization and typically requires a formal system specification.

Common mistake note:
Common mistake: Choosing B or C, which aren't direct advantages of model checking. Performance optimization isn't its focus, and some prior knowledge is needed for specifying the system.

Problem 3 (:3):
Which programming paradigm is particularly suitable for formal verification?
A) Procedural
B) Object-oriented
C) Functional
D) Event-driven
Correct Answer: C

Solution:
Functional programming, with its focus on immutability and pure functions, simplifies code reasoning, making it more suitable for formal verification.

Explanation:
Procedural, object-oriented, and event-driven paradigms can be verified but don't offer the same level of simplicity and clarity for formal reasoning as functional programming does.

Common mistake note:
Common mistake: Choosing A, B, or D, which may still allow verification but don't provide the same level of simplicity and clarity for formal reasoning as functional programming.

What is a common tool used in interactive theorem proving?

Problem 6 (:6):
What is the primary goal of using type systems in program verification?
A) To enhance code readability
B) To ensure memory safety
C) To optimize compilation time
D) To reduce development time
Correct Answer: B

Solution:
The main objective of type systems is to ensure memory safety by preventing operations that could lead to errors, such as accessing invalid memory locations or mixing data types.

Explanation:
Type systems contribute to code readability and can indirectly impact compilation time and development time, but their primary purpose is memory safety.

Common mistake note:
Common mistake: Choosing A, C, or D, which are secondary benefits of type systems but not their primary goal in program verification.

Problem 7 (:7):
Which technique compares a program's output with that of a reference implementation?
A) Property-based testing
B) Equivalence partitioning
C) Regression testing
D) Contract- based programming
Correct Answer: C

Solution:
Regression testing verifies that code changes don't introduce new bugs by comparing program output with previously known correct results.

Explanation:
Property-based testing, equivalence partitioning, and contract-based programming are different verification techniques that do not involve direct comparison with a reference implementation.

Common mistake note:
Common mistake: Choosing A, B, or D, which are other software testing techniques but not the one that compares program output to a reference implementation.
